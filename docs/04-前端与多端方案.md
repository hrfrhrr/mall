# 04 · 前端与多端（小程序）方案

## 1. 双前端策略

| 端 | 技术栈 | 目录 | 服务对象 |
|---|---|---|---|
| 管理后台 | Vue3 + Vite + Element Plus + Pinia + Axios | `frontend/` | 运营/客服/管理员（PC） |
| 用户多端 | uni-app (Vue3) + Vuex/Pinia | `mobile/` | C 端用户：H5、微信小程序、App |

> 两端共用同一套后端 API（网关统一出口），登录态统一为 JWT。

## 2. 管理后台（frontend）

- **请求层**：`utils/request.js` 封装 Axios，`baseURL=/api`，请求头自动携带 `Authorization: Bearer <token>`；401 自动跳转登录页；
- **权限**：路由守卫 + Pinia 用户态；后续按 `bz_permission` 表做按钮级权限（`v-permission` 指令）；
- **工程化**：Vite 别名 `@`、环境变量 `.env.development/.env.production`、ESLint + Prettier；
- **部署**：多阶段构建产出静态资源，Nginx 托管并反代 `/api` 到网关。

## 3. uni-app 多端（mobile）

- **一套代码三端运行**：H5（浏览器）、微信小程序、App（uni-app + uni_modules）；
- **开发工具**：HBuilderX（推荐）或 CLI：`npx @dcloudio/uni-cli create` 风格工程；
- **请求封装**：`api/request.js` 基于 `uni.request`，统一处理 code/msg/token 过期；
- **登录态**：`uni.setStorageSync('token', jwt)`，小程序端登录后可绑定微信 OpenID（规划 `baizhan-auth` 微信授权接口）；
- **域名白名单**：小程序要求 HTTPS 合法域名，开发阶段可在微信开发者工具勾选"不校验域名"；
- **运行方式**：
  - H5：`npm run dev:h5`（Vite 代理 `/api` → 网关）
  - 微信小程序：HBuilderX 菜单「运行 → 运行到小程序模拟器 → 微信开发者工具」

## 4. API 契约（核心接口）

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/auth/login` | 登录（admin/user 双体系） | 否 |
| POST | `/api/auth/register` | C 端注册 | 否 |
| GET | `/api/auth/check` | 令牌校验 | Bearer |
| GET | `/api/user/me` | 当前登录用户 | Bearer |
| GET/POST | `/api/user/addresses` | 收货地址列表/新增 | Bearer |
| GET | `/api/product/goods/page` | 商品分页 | 否 |
| GET | `/api/product/goods/{id}` | 商品详情 | 否 |
| GET | `/api/product/ads` | 首页广告位 | 否 |
| POST | `/api/order/create` | 下单（演示） | Bearer |
| GET | `/api/order/page` | 我的订单 | Bearer |

## 5. 联调注意事项

1. 两端开发服务器均通过代理访问 Higress 网关 `8080`，避免跨域；
2. 管理后台与 C 端 token 隔离：`type=admin` 与 `type=user` 分开存储，各业务服务按 `baizhan.jwt-auth.skip-paths` 区分公开接口；
3. 图片资源统一走 MinIO（`http://<host>:9000/baizhan/...`），生产换 CDN 域名；
4. 后续迭代：管理后台补 RBAC 权限页面；uni-app 补购物车、支付（微信 JSAPI/V3）、物流查询。
