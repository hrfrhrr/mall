# 03 · 亿级高并发设计方案

> 目标：商品浏览 10w+ QPS、秒杀 1w+ QPS、订单异步化、系统可横向扩容。

## 1. 流量分层模型

```
用户请求
  │
  ▼
CDN（静态资源/商品图片，命中率 > 90%）
  │
  ▼
Nginx（接入层限流 limit_req、负载均衡）
  │
  ▼
Gateway（Sentinel 网关流控、JWT 鉴权、黑名单）
  │
  ▼
业务服务（本地缓存 Caffeine → Redis 集群 → MySQL）
  │
  ▼
RocketMQ（异步下单、削峰填谷）
```

## 2. 多级缓存

| 级别 | 介质 | 内容 | TTL | 说明 |
|---|---|---|---|---|
| L1 | Caffeine 本地缓存 | 商品基础信息、类目树、秒杀场次 | 1~5 min | 抗热点 Key，注意本地缓存一致性 |
| L2 | Redis 集群 | 商品详情、库存、用户会话 | 10~30 min | 单 Key 加随机 TTL 防雪崩 |
| L3 | MySQL | 全量数据 | - | 读写分离，从库扛查询 |

**防三坑**：
- 缓存穿透：布隆过滤器 / 空值缓存（短 TTL）；
- 缓存击穿：热点 Key 互斥锁（Redis SETNX）；
- 缓存雪崩：TTL 随机抖动 + 多级缓存兜底 + 限流降级。

## 3. 秒杀核心流程（baizhan-seckill）

```
活动开始前：
  1. 秒杀商品库存预热到 Redis（Lua 原子加载）
  2. 生成秒杀令牌（sign）下发给前端，防止脚本刷单

活动中：
  3. 请求 → Sentinel 限流（QPS 阈值 + 排队等待）
  4. Redis Lua 预扣库存（原子）：扣减成功→生成"资格令牌"写入 Redis
  5. 发送 RocketMQ 事务消息（半消息 → 本地事务落"秒杀订单"→ 提交）
  6. 前端轮询/WebSocket 接收下单结果

活动后：
  7. 消费者异步创建正式订单 + 扣减 MySQL 库存（最终一致）
  8. 超时未支付 → RocketMQ 延迟消息（18 级延迟）→ 关单回滚库存
```

关键 Lua（预扣库存）思路：

```lua
-- KEYS[1]=库存Key ARGV[1]=扣减数量
if (tonumber(redis.call('get', KEYS[1]) or -1) < tonumber(ARGV[1])) then
  return 0            -- 库存不足
end
redis.call('decrby', KEYS[1], ARGV[1])
return 1
```

## 4. 数据库层

- **无外键**（项目约定）：关联关系由应用层维护，便于分库分表；
- **分库分表**：`bz_orders` 按 `user_id % 128` 分表、`user_id % 8` 分库，基因法嵌入订单号避免跨库查询；
- **读写分离**：ShardingSphere-Proxy / 主从 + 注解路由；
- **热点行**：库存扣减拆分为"库存分片 + 汇总扣减"，避免单行锁竞争；
- **归档**：三个月前订单迁移历史库（TiDB/OSS）。

## 5. 可靠性设计

| 场景 | 方案 |
|---|---|
| 重复下单 | 幂等：唯一索引（user_id+sku_id+活动id）+ 令牌一次性 |
| 超卖 | Redis 预扣 + MySQL 乐观锁/条件更新兜底 |
| 消息丢失 | RocketMQ 事务消息 + 消费端幂等 + 对账补偿 |
| 服务雪崩 | Sentinel 熔断降级 + 线程池隔离 + 兜底页面 |
| 分布式事务 | Seata AT（订单-库存-优惠券）或最终一致性（MQ） |
| 灰度发布 | Nacos 权重/元数据 + 网关路由规则 |

## 6. 可观测性

- 日志：Logback + ELK（或 Loki）；
- 指标：Micrometer + Prometheus + Grafana；
- 链路：Micrometer Tracing（Zipkin/Jaeger），网关生成 `traceId` 透传；
- 压测：JMeter/wrk 全链路演练，重点验证 Redis 热点与 DB 瓶颈。
