# 01 · 总体架构设计方案

> 项目：亿级高并发电商平台（Spring Cloud Alibaba 生态）
> 约定：数据库表不设置外键（读写性能优先，一致性由应用层/最终一致性保障）。

## 2. 技术选型

| 层次 | 技术 | 版本 | 选型理由 |
|---|---|---|---|
| 基础框架 | Spring Boot | 3.2.x | 主流稳定，JDK17 原生支持 |
| 微服务 | Spring Cloud | 2023.0.x | 与 Boot 3.2 对齐 |
| 阿里生态 | Spring Cloud Alibaba | 2023.0.1.x | Nacos 注册配置中心、Sentinel、Seata |
| 网关 | Higress（云原生网关） | 1.x/2.x | 基于 Envoy，性能优于 SCG，Nacos 服务发现，兼容 Ingress 注解 |
| 服务间调用 | Apache Dubbo | 3.3.x |  Spring Cloud Alibaba 生态 RPC 框架，Nacos 注册， triple/dubbo 协议 |
| 持久层 | MyBatis-Plus | 3.5.x | 开发效率高，分页/多租户/乐观锁开箱即用 |
| 缓存 | Redis | 7.x | 缓存、分布式锁、秒杀库存 |
| 消息队列 | RocketMQ | 5.x | 事务消息、延迟消息（订单超时取消） |
| 对象存储 | MinIO | 最新 | 自托管 S3 兼容，商品图片 |
| 认证 | JWT (jjwt) | 0.12.x | 无状态，网关统一鉴权 |
| 接口文档 | Knife4j (OpenAPI3) | 4.5.x | Boot3/Jakarta 兼容 |
| 前端 | Vue3 + Vite + Element Plus | 3.5/5/2.9 | 管理后台 |
| 多端 | uni-app + Vue3 | 最新 | 一套代码 H5 + 微信小程序 + App |
| 部署 | Docker + Docker Compose | - | 本仓库交付物，可平滑演进 K8s |

## 3. 服务拆分与端口规划

| 服务 | 端口 | 职责 |
|---|---|---|
| higress | 8080/8001 | 云原生网关（HTTP 入口 / 控制台），Nacos 服务发现路由 |
| baizhan-auth | 9101 | 登录注册、签发 JWT |
| baizhan-user | 9102 | 用户信息、收货地址 |
| baizhan-product | 9103 | 商品、类目、首页广告 |
| baizhan-order | 9104 | 订单创建/查询/超时关闭 |
| baizhan-cart | 9105 | 购物车（规划） |
| baizhan-pay | 9106 | 微信/支付宝支付（规划） |
| baizhan-seckill | 9107 | 秒杀活动（规划） |
| baizhan-admin | 9108 | 运营后台 RBAC（规划） |

规划中的服务同样沿用本仓库脚手架模式，迭代时逐个补齐即可。

## 4. 统一规范

- **包结构**：`com.baizhan.mall.{service}.{controller,service,mapper,entity,dto,vo,config}`
- **响应体**：`Result<T>{code,message,data}`，全局异常处理见 `common-core`
- **鉴权链路**：Higress 只做路由 → 各业务服务通过 `common-security` 拦截器自行校验 JWT（无状态共享密钥）→ 登录用户信息存入 `UserContext`（ThreadLocal）
- **服务间调用**：跨服务调用走 Dubbo RPC（接口与 DTO 统一定义在 `baizhan-api` 模块，provider/consumer 共同依赖），不再走 HTTP 直连
- **数据库**：表名统一 `bz_` 前缀；无外键，关联查询在应用层完成；大表（订单）按 `user_id` 分库分表预留
- **接口版本**：`/api/{domain}/v1/...`（当前脚手架为 `/api/{domain}/...`，后续平滑升级）
